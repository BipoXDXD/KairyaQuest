# Atualização de OpenTelemetry no lock Python

Refs #208. Revisão-base `0adeab9a2306b39c76a3b9c8b79e7feb861d376a`,
conferida contra a `main` no GitHub em 18/11/2026.

## Alteração

O patch atualiza somente a distribuição transitiva `opentelemetry-api` de
`1.45.0` para `1.45.2`. O FastAPI continua em `0.142.2`. A comparação
estruturada dos lockfiles confirmou a igualdade das demais entradas e dos
metadados. As URLs, os tamanhos e os SHA-256 do wheel e do sdist conferem com
os dados publicados no PyPI. `git apply --check`, a verificação da aplicação
reversa e `git diff --check` passaram.

- SHA-256 do `uv.lock` da base
  `5684a8bd3c651d3f4fa9fd6f4729cdf7d4d75c553515a76789cbeab2ce668650`
- SHA-256 do `uv.lock` com o patch
  `c8122571c24de698548aed1e7b31fbb573c681378133b2d48a381d805e0dcd0f`

## Validação local

`make bootstrap` passou na base. No worktree com o patch,
`uv sync --locked` e `uv pip check` passaram no Python 3.14.10, com e sem
dependências de desenvolvimento. No ambiente sem dependências de
desenvolvimento, `GET /health` respondeu 200 com cabeçalhos W3C válidos.
Um teste direto do propagador preservou o identificador de trace, o
identificador de span e o `tracestate` recebidos.

Para o gate, foi usado um PostgreSQL 18.6 temporário, em container
dedicado com porta dinâmica em loopback e banco exclusivo do worktree.
Os testes de fixtures Git receberam identidade sintética apenas no processo
do gate. `make check` terminou com código 0.

- `check-handoff` passou.
- `check-web` passou com 2.875 testes e 100% nas quatro métricas de
  cobertura. ESLint, Prettier e TypeScript passaram.
- `check-api` passou com 2.548 testes, 32 subtestes e 100% de cobertura.
  `uv lock --check`, Ruff e mypy passaram.
- `check-proxy` passou com cinco testes.
- `check-e2e` passou com o build do frontend e 235 cenários Playwright,
  incluindo as verificações de acessibilidade com axe.
- `check-secrets` passou sem achados. `check-wheel` confirmou os quatro
  arquivos de prompt no wheel.
