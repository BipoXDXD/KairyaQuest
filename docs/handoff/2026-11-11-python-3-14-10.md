# Python 3.14.10 sem contorno no CI — 2026-11-11

Objetivo: subir o patch do Python de 3.14.9 para 3.14.10 e provar que o gate
passa sem fixar o interpretador por `UV_PYTHON`, só com `.python-version`.

Revisão-base: `3210ad0` (`origin/main`, merge do PR #88).

## Decisões

- `.python-version` passa a `3.14.10`. Ele continua sendo a única fonte da
  versão: o uv lê o arquivo localmente e no CI, e o `pyproject.toml` segue
  pedindo só a série (`>=3.14`, mypy `3.14`), então o `uv.lock` não muda.
- A imagem da API passa a `python:3.14.10-slim-trixie`, fixada por digest
  (`sha256:9aaa4740…f04802f`) nos dois estágios do `docker/api.Dockerfile`.
- Sai o passo `actions/setup-python` dos jobs `check-api` e `check-e2e`. O
  motivo registrado no workflow era que o catálogo de downloads do uv não
  trazia o patch 3.14.9. O catálogo do uv 0.13.7 traz o 3.14.10 (conferido
  com `uv --no-config python list 3.14 --all-versions` e no JSON de downloads
  da versão, que tem a entrada `cpython-3.14.10-linux-x86_64-gnu`). Por isso
  o CI passa a fixar o uv: os dois `astral-sh/setup-uv` (`check-api` e
  `check-e2e`, os únicos do workflow) ganham `version: "0.13.7"`. Sem isso o
  `setup-uv` instalaria o uv mais recente e o CI deixaria de ser
  reproduzível. O `uv sync --locked` baixa o interpretador de
  `.python-version`. A paridade job↔alvo do Makefile não muda: só saiu um
  passo de preparo de ambiente.
- O `docker/api.Dockerfile` continua com `uv:0.12.15`, sem alteração. Lá o uv
  só instala dependências (`UV_PYTHON_DOWNLOADS=never`) e usa o Python da
  imagem base, que já é o 3.14.10; o catálogo de interpretadores do uv não
  entra no build. Subir o uv da imagem seria mudança sem motivo e exigiria
  novo digest.

## Alterações

- `.python-version`
- `docker/api.Dockerfile`
- `.github/workflows/quality.yml` (inclui o `version:` dos `setup-uv`)
- este arquivo

## Comandos e resultados

Sem `UV_PYTHON` no ambiente (`env | grep UV_` vazio), uv 0.13.7:

- `uv run python -V` → `Python 3.14.10` (interpretador do sistema, achado
  pelo uv a partir de `.python-version`).
- `make check` → EXIT 0: 1718 testes Python (+32 subtests) com cobertura de
  100%, 1157 testes do frontend em 55 arquivos, 68 E2E, Ruff e mypy sem erro
  e gitleaks sem vazamentos.

## Pendências

- `docs/HANDOFF.md` ainda descreve o contorno do `setup-python` e o Python
  3.14.9 (seções "Renomeação"/"Atualização do runtime — 2026-10-22"). Este PR
  não o edita (regra do `check-handoff`); a consolidação deve marcar aquele
  parágrafo do `setup-python` como superado por este arquivo.
- P-python-3-14-10-1: o CI depende de o uv fixado (0.13.7) trazer no catálogo
  o patch de `.python-version`. Ao subir o patch do Python, é preciso subir
  também o `version:` dos `setup-uv`; se esquecer, o job falha no `uv sync`. Não verificado no CI por este
  agente (o PR não acompanha o CI).
